# Mikkel's Monster Sketchbook — handoff notes for Claude Code

Christmas 2026 gift: a boss-rush action game for **Mikkel (8)**, the user's nephew, played on an **iPad in landscape**. Every monster is one of Mikkel's own drawings, turned into creatures with Gemini. Design goal: a kid-sized Elden Ring. Fights are won by learning telegraphed patterns (dodge with i-frames, stamina, stagger, phase 2), not by grinding levels, and the game stays kind to kids (no lost progress, tips on death, Story/Brave/Legend difficulty).

The game was built in a claude.ai cloud session (no git repo) and moved here so local tools work, especially **Nano Banana** (Gemini image API), which the cloud sandbox couldn't reach.

## Layout
```
game/            the playable web app (plain HTML/JS/canvas, no build step)
  index.html     screens + CSS; loads the scripts in this order:
  data.js        52 monsters (moves, stats, drops), weapons, charms, armor, tips, difficulty
  audio.js       procedural Web Audio DSP engine: reverb, stereo panning, weapon/charm SFX, monster voices, composed adaptive music
  game.js        engine: input (touch + keyboard/mouse), player, boss AI (generator "moves"), hazards, HUD, render loop
  rigs.js        GENERATED by rig/build.py — puppet part data per monster
  bossfx.js      boss animation (strip deformation + puppet rig renderer)
  lair.js        arena floors, lighting, ambient life, interactive objects (LAIR_EXTRA = per-boss setups)
  hero.js        the knight (drawn in code) + weapon art with material tiers (Iron→Steel→Golden→Crystal→Infernal→Legendary every 3 upgrades)
  ui.js          menus, save (localStorage), forge, settings, map
  a/             art: <id>.webp sprite · <id>_card.jpg intro card · <id>_bg.jpg arena backdrop · rig_<id>.webp puppet atlas
art/raw, raw2/   Mikkel's original Gemini images (m*/n*/h* ids)
art/cut/         512px cut-outs (RGBA) that rigs are built from
art/clean/       ← Nano Banana output goes here (flat #00FF00 background)
rig/build.py     cuts each cut-out into parts using rig/rigs_*.json, inpaints the body, packs atlases, writes game/rigs.js
rig/rigs_*.json  hand-made part outlines per monster: [type, shape, pivot, opts]
                 type: head | jaw | maw | arm | leg | tent | tail | wing
                 shape: ["e", cx, cy, rx, ry, angleDeg] or ["p", [[x,y],...]]   (all coords 0..1 of the 512 image)
                 pivot: [x, y]  · opts: {"z": -1 = behind body, "mouth": 1 = dark gullet behind it, "joint": radius}
tools/           nano_banana.py · import_clean.py · cut.py (old GrabCut cutter) · gridsheet.py (gridded view for annotating)
tests/           serve.js (tiny static server) · simulate_all.js (headless run of all 52 fights; reports errors + render ms)
```
Monster ids: `m27…m42` are the first batch, `n0…n26` / `h0…h14` the later ones. `h6` is **Uncle Hydra**: the user's own three faces, added on purpose.

## Common tasks
- **Play locally:** `npx serve game` (or `python3 -m http.server -d game 8000`) and open it in a browser. Keys: WASD/arrows, J or left-click = attack, Space/Shift or right-click = roll, E = potion, Q = spirit, Esc = pause, Enter in menus. Settings → "Test mode (unlock all)" gives everything plus 5000 bones.
- **Test everything:** `npm i playwright && npx playwright install chromium && node tests/simulate_all.js` (expects `ERRORS []`).
- **Nano Banana clean art → better rigs:**
  1. `pip install google-genai pillow opencv-python numpy`
  2. `export GEMINI_API_KEY=...` (never commit it or paste it into chat)
  3. `python tools/nano_banana.py m30 m31 n25 n9 n8 m39` (area bosses first; no ids = all 52; `--roar` makes open-mouth frames)
  4. `python tools/import_clean.py` keys out the green, aligns to the old cut-out, and rebuilds rigs. Review `rig/align_<id>.jpg`.
  5. If a design changed a lot, re-annotate that monster: `python tools/gridsheet.py rig/sheet.jpg <id>`, edit its entry in `rig/rigs_*.json`, then `python rig/build.py <id>`.
  The model defaults to `gemini-2.5-flash-image`; set `NANO_MODEL` to use a newer one.
- **Rebuild one rig after editing outlines:** `python rig/build.py <id>` (requires opencv-python, numpy, pillow).
- **Deploy to GitHub Pages (`https://sinaakhtar.github.io/mikkels-monster-sketchbook-game/`):** Whenever pushing changes to `main`, push to both the private repo (`origin`) and the public Pages repo (`git push https://github.com/sinaakhtar/mikkels-monster-sketchbook-game.git main`), which triggers `.github/workflows/pages.yml`.

## Design rules worth keeping
- Every attack is telegraphed: red danger shape, then a white ✦ sparkle just before it hits. Rolls have i-frames.
- Lair objects appear only in 17 hand-picked fights (see `LAIR_EXTRA` in lair.js). Monsters must never hurt themselves: their attacks don't set off barrels, and they steer around obstacles and refuse to charge into a pillar they can see. Tricks need player timing.
- Two images of caricatured real public figures (a mosquito and a cobra statue) were deliberately left out. Don't add them.
- The user prefers to test on desktop with keyboard/mouse; the target is touch on iPad.
